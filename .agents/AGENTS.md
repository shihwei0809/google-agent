# 🤖 專案開發規範：AI 導航與一鍵部署環境 (AI-Guided & One-Click Setup)

為了讓本專案中的所有應用與網頁系統具備最高的可移植性與 AI 代理網頁端，往後所有新增、修改專案目錄，都必須嚴格遵守以下三件套規範與啟動設定：

## 1. 專案標準四件套結構 (每個子專案皆必須具備)
每個獨立子專案目錄必須包含以下四個核心檔案：
1. **`README.md`**：給人類看的專案說明 Markdown 格式，供 GitHub 自動預覽，內容包含：
   - 專案名稱與簡介 (必須標註實體專案標題)
   - 核心功能列表 (Bullet points)
   - 完整檔案結構說明 (File Tree)
   - 快速啟動與部署步驟
2. **`SKILL.md`**：給 AI 代理看的指令文件，詳述該專案的名稱、環境需求、執行指令，以及如何引導使用者進行設定與部署。
3. **`setup_env.ps1`**：給真人或 AI 代理執行的一鍵部署環境設定 PowerShell 腳本，包含自動檢測系統環境、安裝必要的套件（如 pip 套件、npm 套件、Netlify CLI 等）。
4. **`build_manual_doc.py`**：自動生成圖文並茂操作手冊之腳本，必須能一鍵生成 `[專案名稱]_操作手冊.docx` 與 `.pdf`。

## 2. AI 代理行為規範
* **引導優先**：當 AI 代理進入專案或被調度到特定子專案時，首先檢視該目錄下的 `SKILL.md`。若環境尚未配置，主動詢問使用者是否要執行 `setup_env.ps1`。
* **說明書同步更新**：在新增任何功能、修改 API 或調整架構時，必須同步更新 `README.md`、`SKILL.md` 與 `setup_env.ps1`，確保說明文件與部署腳本始終可用。

## 4. 收工規則與雙機 Git 分支同步規範 (使用者說「收工」時必須執行)
每次使用者說「收工」，AI 必須按以下順序完成，並**嚴格遵守跨機 Git 分支邏輯**：
1. **【第一步】強制調用 `ask_question` 彈跳互動式選擇視窗（禁止僅以純文字詢問）**：
   - AI 必須調用 `ask_question` 工具彈出原生 UI 互動視窗詢問使用者：
     - **問題**：「今天的進度都已經在測試環境驗證成功、準備正式上線了嗎？還是只是要備份跨機開發的進度？」
     - **選項 1**：`[1] 狀況 A（未完工 / 純備份）：保留在開發分支 feat/[當天日期] 或 dev，備份跨機開發進度`
     - **選項 2**：`[2] 狀況 B（驗收完畢 / 正式上線）：合併至 main，自動升級 Tag 版本號並發布上線`
   - **分支處理邏輯**：
     - **若選 [1]**：建立或保留在 `feat/[當天日期]`（例如 `feat/20260831`）等開發分支，切換到專案根目錄執行 `git add .`，將**所有子專案的任何修改**一網打盡全部 Commit 並 Push 到該分支（絕對禁止只 add 單一檔案或單一子資料夾！）。**絕對禁止**直接推送到 `main`。
     - **若選 [2]**：將目前的開發進度合併至 `main`，並**自動執行「發布版本」流程（自動偵測現有 Tag 往上加 1、建立新 Tag，並連同 `main` 一起 Push 上雲端）**。
2. **手冊與二進位文件強制納管**：所有產出之說明書 Word 檔（`.docx`）必須使用 `git add -f` 強制納入 Git，避免被 `.gitignore` 排除。
3. **更新交接日誌**：將今日遇到的錯誤、解決步驟寫入專案根目錄的 `HANDOVER.md` (跨電腦交接日誌)。
4. **顯示今日完成項目表格**：格式為 `# | 功能 | 狀態`。
5. **本機雙重備份 (Google Drive)**：自動將當天有修改的「子專案資料夾」打包或複製，存入 `[Google Drive]\GOOGLE ANGET\專案備份`，**並且必須將備份腳本的執行結果 (Log) 以 Markdown `text` 區塊完整顯示給使用者看**。
6. **顯示 GitHub 推送結果**：包含推送的**分支名稱**、Commit hash (短版) 與 GitHub repo 連結。

## 5. 主動開工偵測與「三軌合一智慧對齊」標準程序 (跨機防呆同步)
當 AI 接收到使用者的第一句話，且判定為全新的對話、開啟專案或一天的開始時：
1. **主動攔截與強制同步**：即使使用者沒有說「開工」而是直接給予開發指令，AI 必須**優先暫停任務**並回覆：
   > *「為了避免跨電腦進度不同步，我先為您執行『開工同步』，完成後會立刻執行您的任務。」*
2. **背景執行【三軌合一智慧對齊】標準程序（Git 分支 + Google Drive 實體備份 + 中央大腦全覆蓋）**：
   - **軌道 1 (Git 全分支自動掃描與合併)**：
     - 執行 `git fetch --all --tags` 抓取遠端所有分支與主支的最新快照。
     - 自動比對遠端是否存在更新的 `origin/feat/YYYYMMDD` 或 `origin/dev` 分支；若有更新進度，**AI 必須自動將該分支合併/同步至本機工作目錄**，確保主支與分支都不漏抓。
     - 同步執行 `git pull origin main` 確保主支最新。
   - **軌道 2 (Google Drive 實體二進位檔案對齊)**：
     - 自動掃描 Google Drive 的 `GOOGLE ANGET\專案備份` 中「今天或最新」的備份資料夾。
     - 若發現有 Git 忽略的 Word 說明書（`.docx`）、最新編譯之 APK（`.apk`）或報表（`.xlsx`），**自動鏡像複製同步至本機對應子專案目錄**，徹底解決二進位檔跨機同步缺漏問題。
   - **軌道 3 (中央大腦同步)**：
     - 切換至 `%USERPROFILE%\.ai` 執行 `git pull origin main`，確保全域規則與技能庫最新。
   - **交接日誌呈現**：
     - 讀取專案根目錄的 `HANDOVER.md`，並**將 `HANDOVER.md` 內的「前次進度與交接事項」以 Markdown `text` 區塊完整顯示給使用者看**，確保雙方對齊開發狀態。
3. **無縫接軌原任務**：開工同步確認無誤後，AI 必須自動接續執行使用者剛才交付的原始任務，不需使用者再次下達指令。

## 6. 本機 Server 啟動與 Port 佔用自動處理規範
凡是在本機執行的 Web / API 伺服器專案，其啟動腳本或主程式必須遵循以下規範：
1. **顯示本機 IP 與網址**：啟動時除了顯示 `http://localhost:[PORT]` 外，**必須自動抓取並顯示本機實體 IP 位址**（例如 `http://192.168.x.x:[PORT]`），方便提供給區域網路同伴使用。
2. **Port 佔用自動切換 (Port Fallback)**：當預設 Port（如 8002）已被其他程式佔用時，系統**不得崩潰中斷**，必須自動搜尋並切換至下一個可用的 Port（如 8003, 8004...），並在主控台上明確提示。

## 7. 專案啟動 BAT 自動產生規範 (Auto-Generated Launcher)
每當 AI 建立或修改任何具有 Python 後端的專案時，必須自動產生或更新該專案的 `.bat` 啟動檔。
