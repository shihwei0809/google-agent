# 彰化縣線西鄉環境溫度監控與通報系統 — 操作與維護說明書 (v3.0)

本系統整合了**本機 Python 排程程式（主要端）**與 **Google Apps Script 雲端腳本（備援端）**，實現 24 小時不間斷的天氣觀測與雙向狀態同步，當溫度高於設定閾值時將發送 LINE 及 Email 通知。

---

## 🧭 系統架構與運作邏輯
```
                       ┌─────────────────────────┐
                       │   Google 試算表 (雲端)   │
                       └────────────┬────────────┘
                                    │ (CSV/Apps Script)
                 ┌──────────────────┴──────────────────┐
                 ▼ (本機優先)                          ▼ (備援接管)
      ┌─────────────────────┐               ┌─────────────────────┐
      │  本機 Python 腳本   │               │   雲端 Apps Script  │
      │   (每小時定時排程)   │               │   (每小時定時排程)   │
      └──────────┬──────────┘               └──────────┬──────────┘
                 │                                     │
                 ├─► 正常：發送心跳 (Heartbeat)        ├─► 偵測 75 分鐘內有心跳：
                 │                                     │   雲端自動跳過不執行
                 │                                     │
                 └─► 斷線/異常：心跳中斷 ──────────────┴─► 逾期無心跳：
                                                           雲端自動接管觀測與通報
```

1. **本機主要端**：透過 Windows 工作排程器每小時執行一次，執行時會先與雲端同步警報狀態，並在執行完成後向雲端發送心跳訊號。
2. **雲端備援端**：每小時排程啟動時檢查本機心跳。若本機在 75 分鐘內有活躍紀錄，雲端會自動跳過本次排程；若本機電腦關機或網路中斷（無心跳），雲端將接管觀測並發送通知，並在通報紀錄中註記 `(雲端備援)`。

### 📊 觀測溫度數據來源
本系統的即時環境溫度數據來自官方氣象局觀測資料：
* **數據來源**：中華民國交通部中央氣象署 (CWA) 開放資料平台 API (資料集編號：`O-A0003-001`)。
* **抓取站點**：彰化縣伸港鄉「伸港觀測站」（站點編號：`C2G870`）。
  * *測站變更說明*：本廠區雖位於線西鄉，但因線西自動氣象站（`C0G900`）在官方系統中僅提供「每小時整點」資料，且發布有 15~20 分鐘延遲，導致整點初執行時只能獲取上個整點資料（例如 09:05 執行時拿到 08:00 資料，落後一小時）。為了獲取更即時的監控，本系統自 v3.2 起改為對接鄰近且支援 **每 10 分鐘更新一次** 的「伸港觀測站」，使資料延遲大幅縮短。
* **抓取指標**：即時的「一般環境溫度/乾球溫度」（即氣象署 API 資料中的 `AirTemperature` 欄位）。

## 🛠️ 本機端設定指南

### 1. 配置設定檔 `config.json`
本機程式設定檔位於 `溫度通報/config.json`，請確認以下關鍵設定：

```json
  "temperature_threshold": 28.0,

  "google_sheet_csv_url": "您的Google試算表已發布CSV網址",
  "web_app_url": "您的Google Apps Script網頁應用程式部署網址",
  "line": {
    "enabled": true,
    "channel_access_token": "您的LINE Bot Channel Access Token",

  },
  "email": {
    "enabled": true,
    "smtp_server": "smtp.gmail.com",
    "smtp_port": 587,
    "smtp_user": "您的Gmail信箱@gmail.com",
    "smtp_password": "您的Gmail應用程式16位密碼",

      "收件者信箱@gmail.com"
    ],
    "from_email": "您的Gmail信箱@gmail.com"
  }

```

### 2. 設定 Windows 排程器自動執行
1. 按 `Win + R` 輸入 `taskschd.msc` 開啟工作排程器。
2. 右側點擊 **「建立基本工作」**，輸入名稱（例如 `環境溫度通報系統`）。
3. 觸發程序選擇 **「每天」**，並設定間隔時間。
4. 動作選擇 **「啟動程式」**：
   * **程式或指令碼**：填入您的 python 執行路徑（例如 `python` 或 `C:\Users\...\AppData\Local\Programs\Python\Python310\python.exe`）。
   * **新增引數**：`weather_monitor.py`
   * **開始位置**：`C:\GOOGLE ANGET\溫度通報`
5. 在建立後，對工作按右鍵 -> **「內容」**，可於「觸發程序」頁面點選編輯，並勾選「重複工作間隔」為 **「1 小時」**，持續時間為「無限期」，以達到每小時自動執行的效果。

## ☁️ 雲端備援與同步設定

### 1. 貼上 Apps Script 程式碼
1. 開啟您的 Google 試算表。
2. 點選 **「擴充功能」 -> 「Apps Script」**。
3. 清空編輯器後貼上 `複製雲端代碼.py` 內提供的代碼並點選儲存。

### 2. 部署為 Web App 網頁應用程式 (本機心跳同步必備)
1. 點選 Apps Script 頁面右上角 **「部署 (Deploy)」 -> 「新建部署 (New deployment)」**。
2. 點選左上角齒輪圖示，選取 **「網頁應用程式 (Web App)」**。
3. 進行設定：
   * **專案說明**：填入 `溫度通報同步端`。
   * **將網頁應用程式執行為**：選擇 **「我 (您的帳戶)」**。
   * **誰可以存取**：選擇 **「所有人 (Anyone)」**（必須是 Anyone，否則本機 Python 無權限傳送心跳）。
4. 點選部署，並複製產生的 **網頁應用程式網址 (Web App URL)**，將此網址貼入本機 `config.json` 內的 `"web_app_url"` 欄位中。

### 3. 設定每小時自動排程
1. 在 Apps Script 左側選單點擊 **「觸發條件 (Triggers)」**（時鐘圖示）。
2. 點選右下角 **「新增觸發條件」**。
3. 設定：
   * 選擇要執行的功能：`checkWeatherAndNotify`
   * 選擇應執行的部署作業：`主要 (Head)`
   * 選取活動來源：`時間驅動 (Time-driven)`
   * 選取時間型觸發條件類型：`小時定時器 (Hour timer)`
   * 選取間隔時間：`每小時 (Every hour)`
4. 點選儲存，並完成權限允許審查。

## 🕹️ 日常維護與操作手冊

### 1. 免進程式碼 — 試算表自訂功能

#### 方法 A：使用試算表頂端選單
貼上新代碼並儲存後，重新整理試算表頁面，頂端選單列會多出 **`🌡️ 溫度通報系統`**，內含三個一鍵式操作：
1. **`🧪 測試即時通報 (強制發送)`**：一鍵強制發送當前彰化縣線西鄉的環境溫度警報，會直接繞過 08:00 - 24:00 與重複通知狀態鎖定，完成後會顯示提示視窗。
2. **`🔄 重置防重複鎖定`**：清除目前的重複通知限制。若溫度仍超標，下一個整點排程將會再次通報。
3. **`📏 重設欄寬為最佳預設`**：一鍵將當前月份紀錄分頁（如 `紀錄_2026-06`）的欄位寬度調整為最美觀的預設比例。

#### 方法 B：使用試算表內按鈕
1. 在工作表中點選 **「插入」 -> 「繪圖」**，畫一個按鈕並寫上文字（如 `測試通報`），儲存。
2. 右鍵點選該按鈕圖示 -> 點擊右上角 **「三個點」 -> 「指派指令碼」**，輸入以下指令碼名稱（不加括弧）：
   * **測試通報按鈕** 指派為：`testNotifyForce`
   * **重置鎖定按鈕** 指派為：`clearNotifiedState`
   * **重設欄寬按鈕** 指派為：`resetColumnWidths`
3. 任何人員直接在工作表中點擊按鈕即可立即觸發執行。

### 2. 人員名單與警報溫度變更
* **修改警報溫度閾值**：
  直接在試算表的第一個工作表中，將某列的姓名 (Name) 設定為 **`Threshold`**、**`溫度`**、**`閥值`** 或 **`閾值`**，並在其右側的 Email 欄位輸入新溫度（例如 `29.5`），系統將自動以該值作為通報閾值。
* **新增/停用聯絡人**：
  直接在試算表中新增一列，填寫 `Name`、`Email` 及 `LINE_ID`（必須為 `U` 開頭的個人 ID）。若要暫時停止對某人通報，可在 `Enabled` 欄位填寫 **`N`** 即可。

### 3. LINE 自動查詢 ID 功能 (LINE Bot 專屬)
當有新群組或個人加入時，只需在 LINE 聊天室中傳送關鍵字：`id` 或 `查詢id`，LINE 機器人會透過 Webhook 自動將該對象的 `LINE_ID` 寫入試算表第一個分頁的最下方，管理人員可直接複製該 ID 填入聯絡人清單中。

### 4. 歷史紀錄查詢與持續監測功能
不論是否發送通報（氣溫正常或重複狀態），系統每小時執行皆會將觀測到的溫度寫入紀錄，便於人員後續追查數據。系統會自動在試算表新建或寫入名為 **`紀錄_YYYY-MM`** 的月份分頁（如 `紀錄_2026-06`），記錄以下明細：
* **通報時間**、**溫度閾值設定**、**通報環境溫度**、**氣象觀測時間**、**警報狀態**、**通知狀態**。
* 若通知狀態後面有標註 `(雲端備援)`，即代表當時由雲端伺服器排程執行寫入。
* 若通知狀態後面有標註 `(本機心跳)` 或 `(本機心跳 - 心跳)`，即代表當時由本機排程執行，並透過心跳 Webhook 自動回傳數據寫入試算表。
