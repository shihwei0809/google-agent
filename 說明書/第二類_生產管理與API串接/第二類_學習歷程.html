Chapter 01 · Python

🐍 第一次寫Python演算法

IPA生產排程 · 雙儲槽容積預測

一開始我只知道Python能寫for迴圈，根本不知道能拿來做什麼「演算法」。直到我試著把每個小時的流量數據跑一遍，印出來發現它真的預測出了溢槽時間，那個畫面我到現在還記得。
😤 一開始完全搞不懂 🎉 看到預測結果那刻
學到的關鍵概念
▸ 累加迭代 → 模擬時間序列
▸ threshold判斷 → 條件式警報
▸ 雙迴圈並行 → 兩槽同步計算
# 我寫的第一個真正有用的程式 # 簡單，但跑出來的那一刻超興奮 tank_a = 0 tank_b = 0 LIMIT = 100000 # 公升 for hour in range(24): tank_a += flow_a[hour] tank_b += flow_b[hour] if tank_a > LIMIT * 0.9: print(f"⚠ A槽 {hour}時 快滿了！") if tank_b > LIMIT * 0.9: print(f"⚠ B槽 {hour}時 快滿了！") # 輸出："⚠ A槽 14時 快滿了！" # 我：等等，它真的預測到了？！
✨ 成就解鎖：for迴圈跑完我居然真的能預測溢槽時間，那一刻很有成就感

Chapter 03 · Google Apps Script

📊 學習GAS串接

N系列出貨核對 · doPost讓我理解了webhook的概念

GAS的doPost讓我理解了webhook的概念——原來程式可以被「叫醒」，而不是主動去問有沒有新資料。前端POST過去，GAS就醒來，把資料寫進試算表。這個架構讓我覺得：原來雲端是這樣運作的。
💡 webhook的頓悟時刻 ✅ 第一次用GAS當後端
理解過程
BEFORE 我以為程式要一直輪詢問「有資料了嗎？」
AFTER 原來可以等別人主動推過來，GAS就是接收推送的那一端
// GAS Apps Script function doPost(e) { const data = JSON.parse( e.postData.contents ); const sheet = SpreadsheetApp .getActiveSheet(); sheet.appendRow([ data.barcode, data.item, data.qty, new Date() ]); return ContentService .createTextOutput( JSON.stringify({ok: true}) ); } // 前端POST一次，試算表就多一行 // 這簡直是魔法
📌 關鍵學到
▸ webhook = 被動接收推送的端點 ▸ doPost = GAS的接收入口 ▸ deployAsWebApp = 公開為URL

Chapter 05 · 資料庫設計

🗄️ 資料庫遷移挑戰

三合一單 · schema設計錯了重建了三次，但搞定後資料總算有了家

schema設計錯了重建了三次，但搞定後資料總算有了家。第一次設計資料庫時我把所有欄位塞進一張表，後來發現JOIN根本跑不了，只好重建。第三次才搞定正規化。
1
第一次 ❌ 一張大表
所有欄位塞在一起，JOIN無法用，查詢超慢
2
第二次 ⚠ 分太細
拆了七張表，查一筆資料要JOIN五次，崩潰
3
第三次 ✅ 剛剛好
主表＋子表分離，外鍵關聯，資料總算有了家
💡 搞定後寫了 schema.sql 版控，以後部署再也不用手動建表了
-- 第三次：正確的schema設計 CREATE TABLE tri_orders ( id INT PRIMARY KEY AUTO_INCREMENT, form_no VARCHAR(20) UNIQUE, dept VARCHAR(20), status ENUM('draft','done','cancel'), created DATETIME DEFAULT NOW() ); CREATE TABLE tri_items ( id INT PRIMARY KEY AUTO_INCREMENT, order_id INT, item_no VARCHAR(30), qty INT, FOREIGN KEY (order_id) REFERENCES tri_orders(id) ); -- 歷史資料匯入 LOAD DATA INFILE 'history.csv' INTO TABLE tri_orders ...
