🎬 第一個專案

flowchart-web 學習記錄

🗺️
「第一次嘗試 SVG 是最難的」
我以為 SVG 就像畫圖一樣直觀，結果第一天全部時間都花在搞清楚 坐標系是怎麼運作的。viewBox 和 transform 讓我頭痛了整整兩天
🌊
「液位動畫讓我 debug 了兩天」
我想做出那種槽體液面會波動的效果。查了資料發現要用 clipPath， 然後又花了兩天搞清楚為什麼動畫會「跳」而不是「流」。 最後用 requestAnimationFrame 才解決了
🤖
「後來加入 AI，系統活起來了」
整合 Gemini API 那一刻是我最興奮的時候。原本死板的流程圖 突然可以用中文問答，感覺像是賦予了它生命。後來加入 Groq 作備援， 第一次理解了「備援架構」的真正意義
💢 最大挑戰
SVG 坐標系的理解、clipPath 動畫的平滑化、Gemini API 的 CORS 問題 — 這三個加起來差點讓我放棄
⚡ 突破時刻
搞懂 requestAnimationFrame 的工作原理之後，所有動畫問題都迎刃而解了。那一刻我真正理解了「瀏覽器渲染循環」
💭 這個專案讓我學到
純前端也能做出原本以為需要專業軟體才能做的視覺化效果。SVG 的靈活性遠超我的想像
// 液位動畫核心 — 花了我兩天才搞懂 function animateLiquid(level) { const clip = document.getElementById('liquidClip'); clip.style.height = level + '%'; requestAnimationFrame(() => animateLiquid(level)); }
SVGclipPathrAFGemini API
🔧 第二個專案

hongsheng-web 學習記錄

🔥
「第一次接觸 Firebase，頭腦爆炸」
之前都是純前端，所有資料存在 localStorage。Firebase 是我第一次 接觸「真正的後端服務」。光是搞清楚 SDK 要怎麼引入、authentication 是什麼、資料結構要怎麼設計，就花了我整整一個禮拜
⚡
「學到了即時資料同步的原理」
onValue() 這個函數讓我震驚。它不是你去問伺服器「有沒有新資料」， 而是伺服器主動推給你。WebSocket 的魔法第一次親眼所見
🚨
「紅燈警示系統是有成就感的部分」
條碼掃描防錯加上即時警示，第一次讓我感受到「做的東西真的有用」。 同事拿去試用，錯誤率明顯下降，這個回饋讓我很有動力繼續做
💢 最難的地方
Firebase 安全規則的設定讓我困惑很久。一開始把 rules 全部設為 public 就可以用，但我知道這樣在生產環境不行，花了很多時間研究正確的設定方式
⚡ 突破時刻
第一次看到兩台不同電腦上的瀏覽器同步更新狀態時，我站起來歡呼了。那個「即時同步」的感覺真的很震撼，我終於理解了 WebSocket 的威力
💭 這個專案讓我學到
後端不一定要自己架伺服器。Firebase 讓我在沒有 Node.js 後端知識的情況下，也能做出真正的多人即時應用
// 我最喜歡的那行程式碼 onValue(ref(db, 'audit/status'), (snapshot) => { const status = snapshot.val(); // 伺服器推過來了！不用輪詢！ updateUI(status); });
FirebaseWebSocket即時同步條碼掃描
🏭 第三個專案

isotank-training 學習記錄

🌊
「用 CSS 動畫做出管道流動效果」
SVG 的 stroke-dasharray + stroke-dashoffset 動畫，可以做出液體在管道裡流動的視覺效果。 這個技巧在我之前做流程圖時完全不知道，ISOTANK 讓我真正掌握了 SVG 動畫的精髓
🎬
「這是我第一個完整的教育訓練系統」
9 個控制點、時間軸播放、暫停/跳轉功能 — 設計這套 UX 讓我第一次 認真思考「使用者體驗」是什麼。訓練員用起來方便嗎？學員看得懂嗎？ 這些問題讓我開始從使用者角度思考
📦
「離線可用是個重要的設計決策」
工廠某些區域網路很不穩定，所以我刻意設計成純前端、無需網路連線。 這是我第一次把「部署限制」納入設計考量，學會了在技術選擇時 考慮實際使用環境
💢 最難的地方
時間軸的「暫停/繼續」邏輯比我想像的複雜。每個步驟有不同的動畫時長，同步這些動畫和說明文字的切換花了我很多時間
⚡ 突破時刻
用 Promise 鏈把每個訓練步驟串起來的那一刻。每個步驟 resolve 才進下一個，自然地實現了「等待用戶確認才繼續」的流程控制
💭 這個專案讓我學到
技術選擇要考慮使用環境。有時候「最強大的技術方案」並不是最好的選擇，離線可用的簡單方案才符合工廠現場的實際需求
/* 管道流動動畫 */ .pipe-flow { stroke-dasharray: 20 10; animation: flow 1.5s linear infinite; } @keyframes flow { to { stroke-dashoffset: -30; } }

🎤 第四個專案

NoType 語音助理 學習記錄

🖥️
「第一次嘗試 Electron 桌面應用」
Electron 讓我的思維從「網頁」切換到「桌面應用」。 第一次 npm start 跑起來看到自己的網頁出現在一個獨立視窗裡時，感覺很神奇。 但隨之而來的是 Main Process / Renderer Process 的溝通讓我困惑了很久
⌨️
「全域快捷鍵讓我理解了系統層級的事件」
瀏覽器裡你只能監聽「你的網頁」的鍵盤事件。但 Electron 透過 globalShortcut 可以監聽整個作業系統的按鍵，即使視窗最小化也有效。 這讓我第一次理解了「系統層級」vs「應用層級」的差異
🎯
「自動打字輸入是最有成就感的功能」
用 robotjs 把識別結果「打」進任意視窗，這個功能讓同事第一次試用時 當場驚呼「這什麼魔法」。能打進 Excel、Word、任何輸入框， 看到別人因為你做的東西而驚訝，是繼續做下去的最大動力
💢 最難的地方
IPC (Inter-Process Communication) 在 Electron 裡的概念讓我花了很長時間理解。Main Process 和 Renderer 的通訊方式跟我之前理解的任何架構都不一樣
⚡ 突破時刻
第一次成功把錄音、傳送 API、接收識別結果、注入鍵盤事件這四步串起來，整個流程不到 3 秒完成，當下真的站起來拍手慶祝
💭 這個專案讓我學到
網頁技術不只能做網頁。Electron 打開了一扇門，讓我知道 HTML/CSS/JS 可以做桌面應用，未來還能做什麼我開始有更多想像
// 全域快捷鍵 — 突破瀏覽器限制 const { globalShortcut } = require('electron'); globalShortcut.register('Alt+Space', () => { // 即使視窗最小化也會觸發！ startRecording(); });
