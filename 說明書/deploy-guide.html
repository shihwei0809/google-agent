🚀 無限免費部署教學指南

全面掌握 GitHub Pages 與 Cloudflare Pages 的更新與部署流程，告別 Netlify 流量與部署次數限制！

🏠 返回專案總大廳

☁️ Cloudflare Pages (主力推薦)

優勢：全球最快 CDN 節點、無流量限制、每月高達 500 次免費部署額度。

  • 1

    綁定 GitHub 來源

    登入 Cloudflare 後，左側點選 Workers 和 Pages ➔ 建立應用程式 ➔ 切換到 Pages 頁籤 ➔ 點擊 連線到 Git，並授權您的 GitHub 帳號。

  • 2

    選擇專案與設定組建

    選取對應的 `google-agent` 或專案名稱。關鍵設定來了：
    框架預設請選 無 (None)。
    如果在根目錄，請保持預設；如果網頁放在特定資料夾（例如：說明書），請注意中文字元問題（詳見下方避坑指南）。

  • 3

    儲存並部署

    點擊 儲存並部署。只要 GitHub 上的代碼有更新，Cloudflare 就會自動觸發重新部署，完全不需手動操作！

🐙 GitHub Pages (完美備份)

優勢：與程式碼儲存庫完美結合，完全免費，部署次數無上限！

  • 1

    開啟 Settings 設定

    進入您的 GitHub 專案頁面，點擊上方導覽列的 ⚙️ Settings (設定)。

  • 2

    設定 Pages 來源

    在左側選單找到 Pages。
    Source 選擇 Deploy from a branch。
    Branch 選擇 main，資料夾選擇 /(root) 或 /docs，然後點擊 Save。

  • 3

    等待 Actions 執行

    GitHub 會自動啟動背景流程。點擊專案上方的 ▶️ Actions 頁籤，看到綠色打勾圖示 ✅ 就代表部署完成！

⚠️ 人員避坑指南 (常見錯誤總覽)

部署失敗？請先檢查是不是踩到了以下常見地雷：

😵
錯誤一：Cloudflare 顯示 404 找不到網頁

網頁放在名為「說明書」等中文資料夾中，直接將「組建輸出目錄」設為中文，導致 Cloudflare 系統抓取路徑亂碼，發佈了空網站。

✅ 解法：使用指令轉換英文。
在 Cloudflare 組建設定中：
組建命令輸入 mv 說明書 public
輸出目錄輸入 public
🤦‍♂️
錯誤二：Netlify 突然斷線或被暫停

改一個字就推(Push)一次程式碼，或是狂按命令列部署。Netlify 免費版每月只有 300 學分（約可部署 20 次），用完即斷線。

✅ 解法：請將主要流量切換至 Cloudflare Pages 或 GitHub Pages，它們沒有嚴苛的部署次數扣分機制。
🐢
錯誤三：本地改好代碼，線上卻沒更新

在自己電腦上存檔了，就以為網頁會自動變更，卻忘記將修改同步上傳(Push)到遠端伺服器。

✅ 解法：永遠記得「三部曲」：
git add .
git commit -m "更新說明"
git push (這一步才會觸發線上更新！)
🔗
錯誤四：CSS/圖片/JS 載入失敗 (破圖)

在 HTML 裡使用了絕對路徑（例如 /images/pic.png），導致在 GitHub Pages 的子目錄結構下找不到檔案。

✅ 解法：一律改用相對路徑！
將 /images/pic.png 改為 ./images/pic.png。加上小數點 . 是保命關鍵。
