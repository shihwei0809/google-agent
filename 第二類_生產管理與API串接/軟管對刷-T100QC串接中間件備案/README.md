# 🛡️ 軟管對刷 - T100 ERP QC 串接中間件 (備案獨立專案)

> ⚠️ **隔離聲明**：本專案為完全獨立之擴充備案資料夾，**不影響現有 `軟管對刷` 正式運作程式與 APK**。未來正式導入鼎新 T100 ERP 串接時可直接採用此模組。

---

## 📌 專案目的與未來規劃
本專案專門用於銜接 **鴻勝化學現場對刷系統** 與 **鼎新 T100 ERP 品管檢驗單 (如 QC301 / ESQC301 / asqi600)**。

在現場人員進行「儲槽」與「軟管」對刷前，中間件會先向 T100 ERP 查詢該車號/櫃號對應之 QC 檢驗結果：
1. **若 T100 判定為 `PASS` (已審核合格)** ➔ 手機 App 解鎖，允許進行軟管對刷與卸料。
2. **若 T100 判定為 `REJECT` 或 `待檢驗`** ➔ 手機 App 自動發出警報並阻斷提交，防止未檢合格之化學品誤卸。

---

## 📂 檔案架構
- **`t100_qc_middleware.php`**：T100 QC 檢驗結果查詢 RESTful API 中間件（含詳細註解與高彈性設定陣列）。
- **`README.md`**：本說明書。
- **`SKILL.md`**：AI 助理維護說明與開工步驟。
- **`setup_env.ps1`**：一鍵環境初始化與 PHP 測試腳本。

## ⚙️ 高度彈性調整說明 (適應未來 T100 欄位異動)
所有可能隨 T100 異動的參數均收錄於 `t100_qc_middleware.php` 頂部的 `$T100_CONFIG` 陣列中：

```php
$T100_CONFIG = [
    // 💡 允許通過的 QC 單別（未來新增單別只需在此陣列追加）
    'ALLOWED_DOC_TYPES' => ['QC301', 'QC302', 'ESQC301'],

    // 💡 視為合格放行的狀態碼
    'PASS_STATUS_CODES' => ['PASS', 'Y', '1', 'APPROVED'],

    // 💡 模擬測試模式（無實體 Oracle 資料庫連線時可切為 true 測試）
    'SIMULATION_MODE' => true,
];
```

## 🏭 現場傳統閥門與製程硬體改造建議 (備案說明)

針對現場使用傳統手動閥門無法自動鎖定之狀況，提供免大幅更換全自動閥的低成本工程改進備案：

### 1. 彰濱一廠（氮氣 N2 壓料入料）
- **改造標的**：加裝 **N2 氮氣加壓電磁閥 (Solenoid Valve)**。
- **安控邏輯**：N2 電磁閥平時維持斷電關閉，無加壓氣源。當手機 App 判定「T100 QC合格 + 現場對刷一致 + QC刷卡」後，發送 24V 訊號至無線繼電器驅動 N2 電磁閥通電開啟，人員方可手動轉開氣閥壓料。
- **優勢**：控制氣壓管路成本極低，不接觸腐蝕性液體化學品，維護極為簡單。

### 2. 彰濱二廠（2 顆共用型泵浦 Pump）
- **改造標的**：採 **Pump 啟動許可陣列 (Permissive Interlock Signal)**。
- **安控邏輯**：共用 Pump 不全關。當某一區對刷合格時，系統僅發送該區獨有的 Pump 啟動許可；若出現 Mismatch 誤接，僅阻斷該區啟動按鈕，完全不影響另一顆為合規管線運轉之泵浦。

### 3. 電磁閥訊號接收架構 (Wi-Fi 無線繼電器)
- **架構**：`[手機 App / Server 對刷過關]` ➔ `[廠區 Wi-Fi / Ethernet]` ➔ `[工業級無線繼電器 (如 ADAM-6060 / Modbus Relay)]` ➔ `[輸出 24V DC / 110V AC 驅動電磁閥線圈]`。
- **安控開關**：亦可於卸料站旁安裝帶綠燈之實體防爆控制盒，對刷過關後綠燈亮起，人員手動按下加壓開關啟動 N2 電磁閥，確保作業安全。
